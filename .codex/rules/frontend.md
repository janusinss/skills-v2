# Active Frontend Implementation (`frontend.md`)

Use this guidance when designing, building, or refactoring UI. Preserve the existing framework, behavior, content, and approved design unless the user requests a change. Enforce [UI_Always.md](UI_Always.md) for core layout, touch target, and CSS hygiene standards, and [MOTION.md](MOTION.md) for animations, spring physics, and micro-interactions.

## Stage 1: Target Aesthetic, Scoping & Component Intake
- **Modern Tech Stack Default (Greenfield Builds):** When starting a new project or scaffolding a new frontend application, always default to a modern component framework stack (**Next.js App Router + React 19 + TypeScript + Tailwind CSS + shadcn/ui + Motion / `@bsmnt/scrollytelling` + GSAP**, or Vite + React + TypeScript + Tailwind CSS, Astro, or SvelteKit). **Never default to or output vanilla HTML/CSS/JS** unless the user explicitly asks for vanilla or the existing codebase is already vanilla.
- **UI Scoping & Design System:** Read the relevant project files and existing `DESIGN.md` or `PRODUCT.md`. When building new views or complex interfaces, use [prompt-enhancer-frontend](../skills/prompt-enhancer-frontend/SKILL.md) to define the P0–P3 component matrix, state variants, and responsive journeys. Prefer [impeccable](../skills/impeccable/SKILL.md) as the primary visual design and craft skill alongside [design-taste-frontend](../skills/design-taste-frontend/SKILL.md) or [frontend-design](../skills/frontend-design/SKILL.md) when their scope fits.
- **Component Intake (Scrollytelling, ThreeUI & Registries):** Prefer the project's existing components and tokens.
  - **Scrollytelling, ThreeUI & Registry Packages:** Check external packages before assuming they are installed (`npm install @bsmnt/scrollytelling gsap` for scroll-driven timelines, pinned stages, and canvas/3D scrubbing via [scrollytelling](../skills/scrollytelling/SKILL.md); `npm install @designcodeio/threeui three @types/three` for ThreeUI shaders; `npx shadcn@latest add "<url>"` for standard registry items).
- **Token Adherence:** Map all typography pairings, tinted palettes, spacing, and border radii to `DESIGN.md` CSS variables in `:root` (no unapproved fonts, raw `#000000`, or untinted `#808080`).

## Stage 2: Composition, Motion & Anti-Slop Standards (via [impeccable](../skills/impeccable/SKILL.md))
- **Primary Visual Craft & Spatial Composition ([impeccable](../skills/impeccable/SKILL.md)):** Use [impeccable](../skills/impeccable/SKILL.md) as the primary design engine when creating or refactoring UI—load [craft-floor.md](../skills/impeccable/reference/craft-floor.md) and [layout.md](../skills/impeccable/reference/layout.md) (plus [typeset.md](../skills/impeccable/reference/typeset.md) and [colorize.md](../skills/impeccable/reference/colorize.md) when tuning typography or color):
  - **Visitor Mode, Spatial Thesis & Concentric Geometry:** Align composition with the surface's visitor mode (`Persuade`, `Operate`, `Read`, `Experience`). Establish a clear reading order that passes the squint test, group by proximity before adding containers, pair tight internal grouping with generous section separation on a `4px` base scale (honoring `DESIGN.md` `DESIGN_VARIANCE`, `VISUAL_DENSITY`, and `MOTION_INTENSITY` dials when present), and calculate concentric nested radii (`R_inner = Math.max(0, R_outer - Padding)`).
  - **Dashboard Telemetry & Density Hygiene (`1-to-3` / `85%-15%` Rule):** Enforce a **Single Source of Metric Truth**—never repeat the same KPI across headers and cards, never duplicate date pickers or filters inside individual cards (use one unified page-level control bar), and never add decorative tip banners or 3D globes. Enforce `1` focal element per zone (max `3` data points per card) and keep `85%` of primary workflows at `0` clicks while collapsing `≥ 5` secondary actions into popovers.
  - **Typography, Color & Browser Surfaces:** Enforce high typographic hierarchy (`65ch–75ch` measure, `H1 ≤ 2 lines`, hero subtext `≤ 20 words`, `-0.02em` to `-0.03em` display tracking, zero single-word colored/italic serif `<span>` headline accents, zero serif fonts inside software dashboards), committed color calibration (hue-tinted secondary text and neutrals, WCAG AA `≥4.5:1` body / `≥3:1` large text, zero First-Order purple or Second-Order `#10B981` emerald defaults), single-source elevation (crisp `1px` border OR offset shadow, never both), and themed browser surfaces (text selection, caret, scrollbars, `:focus-visible` rings, `tabular-nums`).
- **Motion & Micro-Interactions:** Delegate all transitions, spring physics (`stiffness`/`damping`), deterministic rest states, and `@media (prefers-reduced-motion: reduce)` fallbacks strictly to [MOTION.md](MOTION.md).
- **Canonical Anti-Slop & Copy Floors (Unless explicitly overridden in the user brief):**
  - **Structural Anti-Slop Floor:** Enforce Sections 1, 5, and 6 of [UI_Always.md](UI_Always.md) and [craft-floor.md](../skills/impeccable/reference/craft-floor.md) as the single canonical baseline (header `< 80px`, 8-State Interactive Primitives, no floating eyebrow pill badges or kickers above headings, no centered hero + fake macOS traffic-light windows, no ghost cards or `backdrop-blur` over blobs on static cards, no decorative `border-left` side-tab stripes, no stacked icon-tiles above headings, max 1-level container depth without empty Bento cells, and no decorative gridlines or radial halo glows).
  - **Iconography & Authentic Photography:** Enforce Section 4 of [UI_Always.md](UI_Always.md) (accessible domain-specific Lucide/Phosphor SVG icons at `16px`/`20px` `1.5px` stroke, zero Unicode emojis as UI icons, zero reflexive **"Lucide Five"** `Sparkles`/`Zap`/`Shield`/`Check`/`BarChart3` filler icons, zero placeholder URLs, and real photography with `object-fit: cover` and contrast scrims rather than unrequested AI-generated showcase imagery).
  - **Natural Voice & Anti-AI Writing (`avoid-ai-writing`):** Enforce Section 7 of [UI_Always.md](UI_Always.md) as the single canonical copy floor (ban all Tier 1A machine vocabulary, hollow intensifiers, `"It's not X — it's Y"` rhetorical tropes, em dashes in titles/headers/buttons, decorative emojis in section headings, spelled-out numbers instead of Arabic numerals `3 steps`, `10x`, and fabricated `"Jane Doe"` / `"99.99%"` vanity data; avoid unsupported product claims).

## Stage 3: Bounded Quality Audit (via Impeccable)
- If Impeccable is installed, run `.codex/skills/impeccable/scripts/impeccable.cmd detect <file-or-dir>` (or Unix `.codex/skills/impeccable/scripts/impeccable detect <file-or-dir>`). Resolve contrast, rhythm, and token findings in a single bounded pass while preserving intentional design choices.

## Stage 4: Real Browser & Responsive Verification
- Verify substantial layout changes and meaningful interactions in a real browser across mobile (`375px`), tablet (`768px`), and desktop (`1280px`) widths strictly following Section 8 of [UI_Always.md](UI_Always.md). Check zero horizontal overflow (`scrollWidth > innerWidth`), zero unexpected console errors, and ≥44px touch targets, saving screenshots in `scratch/` when visual evidence helps.
